**Details the step decided to make an approved item work (the review judges each):**

- _cache_path makes the caches folder on every call (exist_ok=True), so it exists from the first time any cache path is needed. LOCPOT's path is asked for at parse time, so LocpotManager no longer needs a folder rule.
- The prints of the existing topo caches still show the bare cache name, not the full path (print text unchanged).
- LocpotManager's cache_path is a required keyword-only argument (LocpotManager(filepath, spin_mode=None, *, cache_path)). A default (a fallback path, or None meaning no cache) would have been a second folder rule or a new behaviour. An external caller of the old LocpotManager(filepath) now gets a clear TypeError. No caller outside simulator.py exists in LDOS_spread_decomp.
- Key text: floats are written exactly with repr. The snapped ends and Map's samples are written as their DOS sample energies, with ZERO_V written as '0 V'. LDOS h is written as f'{ldos_h}', the same spelling as the topo names (2 and 2.0 give different keys). The broadening, unit cells and precision use the existing name suffixes, so every disk cache agrees on what 'the same broadening' is (3 decimals). The grid is grid_res.
- File contents. Main file: 'key', 'ld_total' (float32, points x energies x atoms x orbitals), 'energies' (float64: Line/Path the eg, Map energies[map_e_idx]), 'current' (float32) and 'z' (Line/Path the stripe's heights, Map map_z). Mag file: 'key' and 'ld_mag'. The GPU energies of the current (cached_current_E, map_current_E) are not stored; they are formed again from the samples as before.
- A file that cannot be read, or whose stored key differs, counts as no match: the data are calculated and saved over it.
- Loads print '[*] Loading Cached <view> LDOS[, mag channel]: <name>', like the topo cache loads. Saves print nothing.
- A Line/Path hit also replaces the view's heights when only the window changed (needs_topo False), so the loaded LDOS always goes with the heights it was calculated at.
- On a hit the mag channel is not loaded with the total. While Mag is on, the existing needs_mag path is reused, now trying the _mag file first.
- Map's needs_mag and the dragged-map save build the key from Map's kept records (map_bias, map_ldos_h, map_window, map_d_ldos, map_broadening, map_e_idx), not the window's, so the key describes the data even when the window has changed since.
- The dragged map is saved only when its snapped sample changed (samples_changed). Otherwise the key is unchanged and its file already holds these maps. The save happens after the sort, so the stored samples and columns are in increasing energy.
- A Line/Path hit still calls _ensure_ldos_topo first: section 5's LDOS topo panel rule, unchanged. A Map hit still takes the LDOS topo in needs_topo and for the markers' spectra (unchanged). Only the maps' LDOS and the stripe are skipped.

**Blockers:** none. **Additional changes:** none.
